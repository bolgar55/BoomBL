# 07 — Интеграция, деплой и инструкция

**Требования:** R34, R36, R38, R40, R41
**Blocked by:** 04, 05, 06
**Зона:** `app.js` (точка входа, связывающая модули), `vercel.json`, `.env.example`, `README-deploy.md`
**Волна:** 4
**Status:** ready

## Что должно заработать

Всё построенное в тикетах 01–06 связывается в одно рабочее приложение через единую точку входа. Проект готов к деплою на Vercel одной командой: статика игры и `/api/*`-функции в одном бесплатном проекте, HTTPS из коробки. Инструкция по деплою пошагово описывает: деплой на Vercel, получение `GAME_URL`, настройку Menu Button/`/newapp` в BotFather с этим URL, настройку вебхука бота, куда вписать уже имеющийся `TELEGRAM_BOT_TOKEN`. Комментарии во всех файлах проекта — на русском (сквозная проверка).

## Из брифа, дословно

> «В @BotFather включить Menu Button и указать URL веб-приложения (/setmenubutton), либо настроить Web App через /newapp»
> «Разместить игру на HTTPS-хостинге (обязательно HTTPS — Telegram Mini Apps не открывают http)»
> «Инструкцию по деплою (хостинг с HTTPS, настройка BotFather)»
> «Комментарии в коде на русском или английском (уточнить предпочтение)» → «Русский»
> «Полный рабочий код игры (frontend) с логикой Block Blast»

## Разделы спецификации

Истории 40–42, Решения §11 (хостинг), Открытые места (`GAME_URL`).

## Критерии приёмки

- [ ] Игра открывается и полностью играбельна от `index.html`, все модули 01–06 подключены и работают вместе без консольных ошибок
- [ ] `vercel.json` и структура проекта позволяют задеплоить одной командой (`vercel --prod`) без ручной правки конфигурации
- [ ] `.env.example` содержит `TELEGRAM_BOT_TOKEN` (пусто) и `GAME_URL` (плейсхолдер), без реальных значений
- [ ] `README-deploy.md` — пошаговая инструкция: деплой на Vercel → получить `GAME_URL` → вписать в BotFather (`/setmenubutton` или `/newapp`) → указать `GAME_URL` в коде бота → настроить вебхук
- [ ] Выборочная проверка файлов проекта подтверждает комментарии на русском
- [ ] Финальный смоук-тест: партия от старта до game over, донат (в тестовом режиме/без реальной оплаты — проверяется вызов `openInvoice`), переключение языка и темы — всё работает в одной сборке
