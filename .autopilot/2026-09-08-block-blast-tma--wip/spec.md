# Спецификация: Block Blast — Telegram Mini App

## Задача

Человек открывает Telegram, нажимает на бота — и за пять секунд оказывается в казуальной головоломке: сетка, фигуры, надо заполнять линии. Без установки отдельного приложения, без регистрации, без входа. Партия быстрая, результат виден сразу, лучший счёт не теряется между заходами. Кто-то хочет просто убить пять минут в очереди; кто-то — набрать рекорд; кто-то, кому игра понравилась, — закинуть автору немного Stars на благодарность.

## Решение

Внутри Telegram, по нажатию кнопки у бота, открывается игра Block Blast: поле 8×8, три фигуры внизу, тянешь на поле, собираешь линии — они взрываются, начисляются очки. Партия идёт, пока есть куда ставить фигуры; как только некуда — экран Game Over с результатом, кнопками «Играть снова» и «Поделиться». Лучший результат помнится и на телефоне, и в другом чате того же аккаунта (через облако Telegram). Раз в день — челлендж с целью, одинаковый у всех в этот день. Есть подсказка, куда поставить фигуру. Тема (тёмная/светлая) и язык (русский/английский) подхватываются автоматически. Отдельная кнопка — задонатить автору через Telegram Stars.

Таблицы лидеров между игроками нет — по решению на брифинге хватает личного рекорда, без своего сервера и базы данных.

## Решения по реализации

**§1. Каталог фигур.** Формы — без поворотов (R10.1), относительные координаты клеток от (0,0):

| Название | Клетки | Размер |
|---|---|---|
| Точка | (0,0) | 1 |
| Домино Г / В | (0,0)(0,1) / (0,0)(1,0) | 2 |
| Тримино Г / В | (0,0)(0,1)(0,2) / вертикальный аналог | 3 |
| Уголок (4 ориентации) | напр. (0,0)(0,1)(1,0) | 3 |
| Квадрат 2×2 | (0,0)(0,1)(1,0)(1,1) | 4 |
| Тетрамино Г / В (4 клетки в ряд) | — | 4 |
| Тетрамино L (4 ориентации) | — | 4 |
| Тетрамино T (4 ориентации) | — | 4 |
| Тетрамино S/Z (по 2 ориентации) | — | 4 |
| Пентамино-линия Г / В (5 клеток в ряд) | — | 5 |
| Пентамино-уголок (4 ориентации) | напр. (0,0)(0,1)(0,2)(1,0)(2,0) | 5 |
| Плюс (пентамино) | (0,1)(1,0)(1,1)(1,2)(2,1) | 5 |

Итого около 24 фигур в каталоге — сопоставимо с оригинальной игрой. Точный список и координаты фиксируются в коде `shapes`, не здесь.

**§2. Формула очков.** Постановка фигуры: +1 очко за каждую занятую клетку. Очистка линий одним ходом: `10 × N²` очков, где N — число линий, очищенных за этот ход (1 линия — 10, 2 — 40, 3 — 90…). Серийный множитель: подряд идущие ходы, каждый из которых что-то очищает, наращивают серию; ход без очистки сбрасывает её в 0; очки за очищающий ход умножаются на `(1 + 0.1 × длина_серии)`, с округлением вниз. Почему так: в брифе названы только принципы («больше очков за линии», «множитель за комбо»), точные числа — инженерная деталь, свободная для решения на этом уровне глубины.

**§3. Определение game over.** После каждого хода и после выдачи новых 3 фигур: для каждой из 3 фигур перебираются все 64 позиции сетки; если хотя бы одна фигура хотя бы в одной позиции проходит `canPlace`, партия продолжается — иначе game over. Дёшево по производительности (максимум 3×64 проверок).

**§4. Ежедневный челлендж.** Индекс шаблона на день = `hash(YYYY-MM-DD локальной даты устройства) % 5`, пять шаблонов: «очисти N линий за партию», «набери N очков», «сделай комбо ×2 хотя бы раз», «поставь N фигур», «доиграй без game over N ходов». Один и тот же день у всех игроков даёт один и тот же шаблон и цель — без сервера, чисто по дате. Прогресс и дата последнего обновления — в `persistence`; при смене даты прогресс обнуляется.

**§5. Палитра.** Полностью как передал пользователь — см. `reference.md`. Играет роль основной темы игры (не заменяется цветами Telegram, см. §6).

**§6. Тема.** У пользователя есть точная авторская палитра под обе темы — используем её как основной источник цвета. От Telegram (`Telegram.WebApp.colorScheme`) берётся только сигнал «тёмная/светлая», а не конкретные цвета — иначе индивидуальная палитра терялась бы в пользу случайных цветов темы конкретного клиента Telegram.

**§7. «Поделиться результатом».** Через `Telegram.WebApp.openTelegramLink` со ссылкой вида `https://t.me/share/url?url=<GAME_URL>&text=<результат>` — не требует своего бэкенда и работает во всех клиентах Telegram, поддерживающих WebApp.

**§8. Донат через Stars.** Клиент вызывает `POST /api/create-invoice {amountStars}`; серверлесс-функция создаёт ссылку через Bot API `createInvoiceLink` с `currency: "XTR"` и токеном бота; клиент открывает её `Telegram.WebApp.openInvoice(url)`. Бот обрабатывает `pre_checkout_query` (подтверждает) и `successful_payment` (ничего не хранит — платёж разовый, лидерборда доната нет). Почему через бэкенд, а не напрямую с клиента: `createInvoiceLink` требует токен бота, а токен не может попасть в клиентский код ни при каких условиях.

**§9. Работа вне Telegram.** `telegram-bridge` при инициализации проверяет `window.Telegram?.WebApp`; если его нет — `theme` берётся из палитры по умолчанию (тёмная), `haptic`/`MainButton`/`openInvoice` становятся no-op, `persistence` сразу использует `localStorage`. Игра остаётся полностью играбельной в обычном браузере — это условие тестируемости и ревью, а не отдельное требование пользователя.

**§10. Стек.** Frontend — HTML5 + CSS + JavaScript (ES-модули) без сборщика и без фреймворка, рендеринг сетки и фигур — Canvas 2D API. Почему: Mini App открывается во встроенном WebView, часто на слабой сети и небогатом железе; React/PixiJS для сетки 8×8 и простых партиклов — вес без пользы. Бэкенд — Node.js, серверлесс-функции Vercel (не Express-процесс) — совместимо с обработкой Telegram-вебхука и не требует своего постоянно работающего сервера.

**§11. Хостинг.** Vercel: статика игры и `/api/*`-функции в одном бесплатном проекте, HTTPS из коробки. Закрывает и R36 (хостинг без своего аккаунта), и минимальный бэкенд бота (R31) одним решением. Бот работает в режиме webhook (не long-polling) — единственный режим, совместимый с серверлесс-функциями.

**§12. Партия не сохраняется между запусками.** Если игра закрыта посреди партии, при следующем открытии начинается новая партия с нуля (сохраняется только лучший результат и настройки). В брифе об этом ничего не сказано; решение принято, чтобы не городить сериализацию ради случая, которого не просили — при необходимости легко добавить позже.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `board` | состояние сетки 8×8 | `canPlace(shape, row, col)`, `place(shape, row, col) -> {clearedRows[], clearedCols[]}`, `canFitAnywhere(shapes[]) -> bool` | внутреннее представление сетки |
| `shapes` | каталог фигур | `generateShapeSet() -> Shape[3]` | случайный выбор из каталога |
| `score` | очки и серия комбо | `addMove({cellsPlaced, linesCleared}) -> {points, comboStreak}`, `reset()` | формулу начисления (§2) |
| `persistence` | лучший результат, настройки (звук, язык), прогресс челленджа | `getItem(key)`, `setItem(key, value)` — оба `Promise` | выбор backend'а: CloudStorage внутри Telegram, `localStorage` вне его или при сбое |
| `challenges` | сегодняшний челлендж и прогресс | `getTodayChallenge() -> {id, goal, progress}`, `reportProgress(event)` | генерацию шаблона по дате (§4) |
| `i18n` | словарь строк, текущий язык | `t(key) -> string`, `setLanguage(lang)`, `detectLanguage()` | структуру словаря |
| `telegram-bridge` | обёртка над `Telegram.WebApp` | `init()`, `getColorScheme()`, `haptic(type)`, `showMainButton(text, onClick)`, `hideMainButton()`, `openInvoice(url) -> Promise`, `shareResult(text)` | проверку наличия Telegram (§9) |
| `ui` | рендеринг, ввод (drag/touch), анимации, звук, экраны | точка входа приложения — сама ничего не выставляет другим модулям | детали Canvas/DOM |
| `bot-logic` | разбор апдейтов Telegram-бота | `handleUpdate(update)` | детали Telegram Bot API |
| `api/create-invoice` | — | `POST /api/create-invoice {amountStars} -> {invoiceUrl}` | вызов `createInvoiceLink` и токен бота |

Швы для тестов: `board`, `shapes`, `score`, `challenges` — чистая логика без DOM и сети, тестируются напрямую через перечисленные сигнатуры. `persistence` и `telegram-bridge` — тестируются через инжектируемый мок стораджа/`window.Telegram`. `ui`, `bot-logic` и `api/create-invoice` — точки входа и интеграция с внешними API, проверяются вручную при ревью, а не юнит-тестами.

## Открытые места

- **`GAME_URL`** (R36, R33) — публичный HTTPS-адрес задеплоенной игры. Пользователь ещё не выбрал хостинг (решено предложить Vercel в инструкции), поэтому адрес неизвестен до деплоя. В коде — `[ВПИШИ-СВОЙ-ДОМЕН]`, используется в кнопке бота и в инструкции по BotFather.
- **`TELEGRAM_BOT_TOKEN`** (R33) — у пользователя уже есть бот и токен (подтверждено на брифинге), но сам токен не запрашивается и никуда не пишется. Пустая переменная в `.env.example`, пользователь вписывает сам в `.env`.
- **Номиналы доната в Stars** (R43) — точные суммы пользователь не называл. Плейсхолдер в коде — `STARS_AMOUNTS = [/* впиши, например 25, 50, 100 */]`, отмечено в финальном отчёте.
